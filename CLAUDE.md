# j.gut illustration portfolio

Portfolio site for José Gutierrez (j.gut), concept artist. Goal: land commissions and studio applications (Riot and similar). The site is a **visual container**, not the full catalogue (Instagram covers that): a cinematic scroll-driven hero, then a light gallery of 5 illustrations, then contact. English UI. The user talks to Claude in Spanish.

Confirmed intent: `docs/intent/portfolio.md`. Approved plan: `~/.claude/plans/tenemos-un-nuevo-proyecto-wondrous-stroustrup.md`.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · GSAP + ScrollTrigger (+ Flip) + `@gsap/react` · Lenis · Canvas 2D · sharp (scripts only) · Vitest · Vercel.
Next 16 differs from older versions: read `node_modules/next/dist/docs/` before using an API you are unsure about.

## Commands

- `npm run dev` — dev server (`.claude/launch.json` → `portfolio-dev`, port 3000)
- `npm run build` · `npm run lint` · `npm run typecheck` · `npm test`
- `npm run optimize:frames` — `assets-source/frameN.jpg` → `public/hero/frameN.webp`
- `npm run optimize:illustrations` — `assets-source/illustrations/*` → `public/illustrations/<slug>.webp` (detail view, long side ≤ 2000) and `<slug>-card.webp` (grid), and regenerates `lib/illustration-images.ts` (paths + pixel sizes; never edit it by hand)
- `npm run subset:font` — rebuilds `app/fonts/shippori-mincho-subset.woff2` from the Japanese text in `lib/hero/copy.ts` (run it after editing any Japanese copy)

## Conventions

- `components/IntroScreen.tsx` is a static title card (logo, "Behind the mask", "Signal incoming") rendered in normal document flow **before** `<ScrollHero />`. It is not a loading screen: it doesn't depend on the hero's assets and doesn't disappear on its own — the visitor scrolls past it into the pinned hero. It holds the page's one visible `<h1>`.
- Hero is **data-driven**: frames, focal points, scroll length and transition feel live in `lib/hero/config.ts`; every word shown over it lives in `lib/hero/copy.ts`. José may later replace the AI-generated frames with his own, so never hard-code frame logic in components.
- Pure animation maths lives in `lib/hero/timeline.ts` (unit-tested); drawing lives in `lib/hero/renderer.ts`.
- Text over the hero is real HTML (sharp, accessible), never drawn into the canvas. Elements marked `data-hero-frame="N"` in `components/hero/HeroOverlay.tsx` are faded per scroll state by `lib/hero/overlay.ts` (DOM writes, no React renders while scrolling). The first frame's vertical kanji "curtain" covers the figure's face, which the focal-point crop keeps at ~43% of the height.
- Intro choreography is CSS (`.hero-in`, `.hero-line`, `.hero-stamp` in `app/globals.css`), triggered by `data-ready="true"` on the hero section.
- Layout rule: the overlay must not collide on a 375px-wide phone (Unbounded is wide). Check with real bounding boxes, not by eye.
- Fonts: Unbounded (display) · Shippori Mincho (vertical kanji, glyph-subset, self-hosted) · JetBrains Mono (cryptic HUD text) · DM Sans (light section).
- Colours (tokens in `app/globals.css`): ink `#07070d`, paper `#f6f1e9`, vermilion `#e5233b`, fog `#8b88a0`.
- Logo: `components/Logo.tsx` (inline SVG, `currentColor`) from `lib/logo.ts`; standalone `public/logo.svg`; favicon `app/icon.svg`.
- Originals (frames, logo) stay untouched in `assets-source/`.
- Any Japanese copy must be reviewed by a native speaker before launch.
- The hero hands off to the light section with a **hard cut, on purpose** (the user rejected a fade/curtain transition): once the pin releases, `GalleryIntro.tsx` — a solid, full-height chapter title ("// My work — illustrations") — is simply next in the DOM, arriving the same static way `IntroScreen` does. Don't reintroduce a cross-fade here without asking.
- Gallery: `lib/illustrations.ts` holds José's 5 real pieces. Pixel facts (paths, width/height) come from the generated `lib/illustration-images.ts`; the words (title, discipline, description, `alt`) are written by hand there. To add or swap a piece: put the original in `assets-source/illustrations/`, add it to `SOURCES` in `scripts/optimize-illustrations.mjs`, run `npm run optimize:illustrations`, then give it copy in `lib/illustrations.ts`. `year`, `tools` and `speedDrawing` are optional and left out until José supplies them — never invent them. `description` is `string[]`, one entry per paragraph. Aurora ("Splash art · Fan art") and Wild Devotion (slug still `tigre`, so its link is `#tigre` and its image files keep that name) carry José's own titles and descriptions, pasted verbatim. Poki opens with his note (second part of a "Queen" series inspired by his wife; written as "the artist's wife" because no name is shown on screen) and the rest was drafted from the artwork; Whitebird and Sacred (titles from the file names) are drafted entirely from what is visible, with no claims about process, tools or inspiration. Replace those drafts when he sends his own wording. `Card.tsx` still renders a stand-in visual whenever `image` is null.
- **Grid order matters.** A landscape piece spans two of the three desktop columns (`sm:col-span-2`), so it goes first and rows fill exactly (2+1, then 1+1+1; 2-col: 2, 1+1, 1+1). `lib/illustrations.test.ts` fails if a reorder would leave gaps at 2 or 3 columns, and also checks that every referenced image exists and matches its recorded size. Cards use plain `<img>` (sizes are pre-generated, so `next/image` would only re-process them) with `alt=""` — the title names the button; the descriptive `alt` lives on the detail view's image. `GalleryIntro.tsx` carries the section's one visible heading (`#gallery-heading`); `Gallery.tsx`'s `<section>` points back to it via `aria-labelledby` rather than repeating it. Non-hero copy lives in `lib/site-copy.ts`.
- Detail view (`DetailDialog.tsx`): a single, always-mounted native `<dialog>` (`showModal()` gives focus trapping and ESC/`cancel` for free), its content swapped per `activeSlug` (state owned by `Gallery.tsx`). The artwork is always shown whole at its own aspect ratio (portrait: beside the text from `lg`; landscape and anything narrower: stacked above it, ≤ ~62vh tall). The pane holds that size in flow and the image box inside it is `absolute inset-0`, so Flip moving it never reflows the dialog; it stacks the card-size image (already cached from the grid, so it fills the box the instant it opens) under the full-size one. Flip runs with `scale: false` (animates width/height): the card crops to 3:4/3:2 while the dialog shows the whole picture, and scaling between two aspect ratios would stretch it in flight. The image box GSAP-Flips to/from the exact clicked card (`Card`'s `boxRef`, tracked in `Gallery`'s `cardBoxRefs` map and read through a `getCardBox(slug)` prop — never pass a dereferenced ref value as a prop, `react-hooks/refs` flags reading `.current` during render). **Flip direction, easy to get backwards**: `Flip.from(state, {targets})` animates a target FROM `state` TO whatever that target's live DOM box is *at the moment `.from()` is called* — so for the open animation, capture `state` from the *card* (small) and target the dialog's box, which is already laid out at its natural (large) size; don't `Flip.fit()` the target small first, or `.from()` has nothing to animate to. The close does the reverse (`Flip.getState` the large box, `Flip.fit()` it small, `Flip.from(largeState, {targets})` back onto that now-small live box) because `Flip.fit()`'s returned value isn't reliably a tween to hang an `onComplete` off. The open piece mirrors to `location.hash` (`#slug`) via `history.replaceState`, so it's directly linkable; test that by reloading a URL that already has the hash, not by setting `location.href` to the same page's hash (browsers treat that as an in-page hash change with no reload).
- Speed drawings (`lib/speed-drawing.ts`): a YouTube URL (`youtube-nocookie.com` embed, recommended for anything long/heavy — screen recordings routinely blow past what's sane to commit or serve from Vercel) or a local path under `public/illustrations/` for a short clip, decided per piece by which kind of string `Illustration.speedDrawing` holds. No real recordings yet — none of the 5 pieces has one.
- Contact (`components/Contact.tsx`, `id="contact"`, the hero CTA's `cta.target`): the closing block, dark and static like `IntroScreen` so the light gallery sits between two ink cards. Copy in `lib/site-copy.ts` (`contact`; the heading is deliberately not "Work with me", which is the hero button); handles and address in `lib/contact.ts`. **The email address never appears in the server HTML**: it's stored in two halves and joined only in the browser — `ContactActions.tsx` (client) sets the mailto `href` after mount and writes the address into the page only when someone taps "Copy email address" (with a fallback that shows it if the clipboard is blocked). Never call `emailAddress()`/`mailtoHref()` during render; check with `curl localhost:3000 | grep -c gmail` → 0. The heading is `clamp(1.25rem,8.6vw,3.25rem)` because Unbounded is wide and "SOMETHING" can't wrap; it fits down to ~230px, so re-measure if the copy changes.

## Git workflow (checkpoints)

- `main` only holds **states the user approved**. Work happens on `feat/<name>` branches with small Conventional Commits (`feat(hero): …`); commits end with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- When the user approves a checkpoint: merge `--no-ff` into `main`, create an annotated tag `checkpoint-NN-<slug>`, push `main` and the tag.
- If a change isn't liked: drop the branch (`git switch main && git branch -D feat/x`). To go back after a merge: `git revert`, or `git reset --hard <tag>` **only with explicit confirmation** (destructive).
- Only commit/push when the user asks or approves a checkpoint. Never `--force`, never `--no-verify`.
- Every branch gets a Vercel preview URL; `main` is production.
